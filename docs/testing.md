# Testing

## Automated checks

```sh
python3 tools/format.py --check
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease
```

Tests cover binary framing and fragmented reads, Swift-compatible control JSON,
pairing reference vectors, HEVC NAL bounds, resolution fallback, source recovery,
reconnection, keyframe retry policy, pointer-move ordering, and pairing-code
grouping with cursor offsets. JVM tests do not
exercise the device's TLS provider, MediaCodec implementation, or Android UI.

Local release assembly produces an unsigned APK; the release workflow signs it
before publication. Successful assembly does not establish hardware
compatibility, security assurance, or store readiness.

## Development device coverage

| Device | Development environment | Observed coverage |
| --- | --- | --- |
| Pixel 6 | Android 17; Exynos HEVC decoder | Pairing, 2560×1440 desktop, phone portrait layout, session recovery, frame timing |
| Xiaomi Pad 7 (2410CRP4CG) | Android 16 / HyperOS 3; Qualcomm low-latency HEVC decoder | Pairing, tablet grid, 2560×1440 desktop, oversized-capture fallback |

These observations were made with the local development builds that preceded
this standalone repository, using Sill for Mac 0.6.0. The standalone application
ID differs from those builds and therefore requires its own pairing. Physical
keyboard, stylus, accessibility, VPN behavior, and long-running stability have
not been validated across this device matrix.

Frame pacing remains a known limitation. Short samples are useful for finding
regressions, but are not a controlled device ranking. The repository intentionally
does not include private desktop screenshots, host identifiers, or raw logs.

## Measurement definitions

- **Receive-to-output:** time from receipt of a complete compressed frame until
  MediaCodec output is dequeued. Includes queueing; not pure decode time.
- **Decoder output rate:** decoded buffers released per second. Not necessarily
  the number of different images displayed by the panel.
- **Presentation timing:** MediaCodec rendered callbacks or SurfaceFlinger
  timestamps. State which source is used; neither is a camera measurement.
- **End-to-end latency:** requires a separate capture/input-to-display method.
  It has not been established by these development tests.

For comparable trials, hold the host, source, resolution, bitrate preset, FPS cap,
transport, and animation workload constant. Separate static-screen intervals from
continuous-motion tests. Do not infer a Wi-Fi-only cause from receive gaps: host
capture, encoding, and reader scheduling can also contribute.

## Protocol fixtures

`app/src/test/resources/swift-wire.json` contains control messages generated by
upstream Swift types. `pair-proof.json` contains a deterministic public test code
and derived HMAC values, with synthetic host/device fingerprint bytes. They are
test vectors, not credentials for a real host.

To regenerate the Swift fixture on macOS, use a separate checkout of the upstream
commit identified in NOTICE:

```sh
swiftc /path/to/sill/Sources/StreamProtocol/StreamMessage.swift \
  /path/to/sill/Sources/StreamProtocol/Input.swift \
  tools/generate-wire-fixtures.swift -o /tmp/sill-wire-fixtures
/tmp/sill-wire-fixtures > app/src/test/resources/swift-wire.json
```

A debug-only UI preview uses synthetic window metadata:

```sh
adb shell am start -n io.github.jf0510.sill/.MainActivity --ez preview true
```

The preview has no live video and does not replace device interoperability tests.

A debug-only connection preview uses synthetic host names:

```sh
adb shell am force-stop io.github.jf0510.sill
adb shell am start -n io.github.jf0510.sill/.MainActivity --ez previewHome true
```

The README screenshots are user-provided captures of live desktop sessions on
Pixel 6 and Xiaomi Pad 7. They illustrate the UI, not measured frame pacing or
latency. `previewHome` overrides connection state only in debug builds; release
builds ignore it.

## Decoder startup regression

In 0.1.12, Xiaomi Pad 7 was checked through three cold launches and connections
to a paired Mac without selecting Desktop manually. Each produced decoded output;
one exercised an early decoder flush and subsequent HEVC configuration resubmission.
The pre-fix failure received frames continuously but produced no decoded output.
This is a focused regression check, not a general latency or stability benchmark.

To repeat the check, launch the app, connect to a paired Mac, and verify the picture
appears without pressing Desktop. In local logs, `Resubmitted HEVC configuration`
identifies the recovery path and `First picture rendered` identifies output handed
to the surface. Confirm the visible picture as well. Raw device logs should remain
private or be redacted before sharing.

The recovery follows Android's [codec-specific data guidance](https://developer.android.com/reference/android/media/MediaCodec#CSD):
a flush before the first output can discard configuration supplied at startup.

Pixel 6 also produced output in three cold-launch connections using the 0.1.13
release build without pressing Desktop. These runs did not exercise an early
decoder flush. The adaptive icon was checked in Pixel Launcher's app search;
the black background fills the circular mask and the monitor retains a margin.
